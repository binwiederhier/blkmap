Three harness bugs surfaced and were fixed; none was in blkmap:

- **mirrorcrash compared by seq, not by order.** A resync copy carries an older seq than a
  write it can land after; when both hit the same slot, the verifier wanted the newer seq and
  reported an acknowledged write as lost (10 of 40 states in the first run). It now requires
  the acknowledged write or one issued after it (`TestJournalResyncOfAnOlderWrite`).
- **Fully hydrated crash states.** A slow recording can hydrate the whole base before it
  ends; such a state starts detached, runs no hydrator and never logs "hydration done". The
  fs check accepts a full COW file as hydrated.
- **`cmd | grep -q` under pipefail.** grep exiting at its first match can fail the pipe with
  SIGPIPE; the checks in crashreplay-run.sh, scenarios.sh, stress.sh and soak.sh use
  here-strings now.

The fs mode needs N=200 as documented: the default N=3000 overfills its 256 MiB guest
filesystem.
