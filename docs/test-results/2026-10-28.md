The CI sequence (`scripts/ci-vm.sh`) on fresh throwaway VMs from the templates passed on
6.8.0-142-generic (template 9002) and 7.0.0-28-generic (template 9000).

The stall probes run a real device against a source that hangs: a server exiting with a
request stuck (no recovery: EIO), closing such a device (with and without a reader that
needs EIO), closing and abandoning it with recovery (the successor completes the reissued
request), a successor taking over a predecessor that is still open, and fail-io recovery.
Measured on 6.8, 7.0.0-30 and 7.0.0-38:

- A successor whose predecessor is still open came up in 0.2 s instead of 30 s per device.
- Fail-io recovery returns EREMOTEIO while no server is attached and re-attaches; 6.8 lacks
  the flag and falls back to queueing.

One blkmap bug surfaced on the way and is fixed in this release: on 7.0 kernels a request a
dying queue loop takes stays owned by the server until the char device is released, and
`Close` issued STOP_DEV first, which wedged the device. `TestQueueDeathFailsDevice` had
failed 5 in 20 runs on 7.0.0-30 and passed on 7.0.0-38 by timing; it now forces the race
(the old code wedged both kernels on the first run) and requires a lost request on 7.0+.
