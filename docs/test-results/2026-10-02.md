## Problems found while getting here

All fixed before this run, each with a test that failed first:

- An acknowledged but unflushed write would revert after a crash once the device survives the
  crash (its bit lived only in process memory): fixed with the live bitmap in `/run/blkmap`.
- Flush requests were rejected by the request range check (the kernel sends sector -1).
- ublk descriptors were not close-on-exec, so a re-executed server (and any child process)
  kept the old device open and recovery was refused.
- The kernel clears the server pid of a device waiting for recovery, so matching the pid made
  the restarted server create a new device instead of re-attaching.
- Without `RestartMode=direct`, systemd ran `OnFailure` on every crash and the reap stopped the
  device before the restarted server could re-attach; on systemd 259 the unit result after
  hitting the start limit is `exit-code`, so the reap condition is now "still failed after
  3 s".
- `systemctl reload` reported failure when the server exited for the handoff; the server now
  re-executes itself in place, keeping its pid.
- `HydrateRun` allocated a buffer before using its pooled one.
- Test harness: `remote-test.sh` exited 0 when scenarios failed, so an earlier run printed
  ALL PASSED wrongly; journal checks raced journald and hit the pipefail SIGPIPE trap.

## Rerun at 18:08 UTC (commit d6a1c96)

After the GitHub Actions bump, the read-ahead test change and a `powercut.sh` fix.

- **First attempt (commit c81f575) failed in the test script, not in blkmap**: cycles 1 to 3
  of the daemon kills passed, then a kill landed while systemd was restarting the unit,
  `MainPID` read 0, and `kill -9 0` killed the SSH session (exit 255). `powercut.sh` now kills
  only a running server, waits up to 30 s for the restarted one, and logs the time.
- **Second attempt: everything passed** in 15 minutes. ublk and device suites PASS, E2E OK,
  STRESS OK, scenarios 36 passed 0 failed, 5 kill cycles (15 kills) and 10 power cuts with
  every acknowledged record intact.
- Each of the 15 kills was followed by the restarted server re-attaching in 1.18 to 1.22 s,
  almost all of it the unit's 1 s `RestartSec`.

## Kernel 6.8 at 19:42 UTC (commit ac246c9)

Same `make test-vm`, on a new template: box11 VM 9002, built from Ubuntu's 24.04 cloud image
with the QEMU guest agent baked in (`virt-customize`), otherwise configured like 9000. The
guest booted kernel 6.8.0-142-generic with systemd 255.

**Everything passed** in 15 minutes: ublk and device suites PASS (including the recovery
tests), E2E OK, STRESS OK, scenarios 36 passed 0 failed, 5 kill cycles (15 kills) and 10 power
